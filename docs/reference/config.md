# Configuration Reference

Rein uses this priority order: environment variable overrides, then the TOML
file from `REIN_CONFIG` or the default config path, then compiled defaults. The
default TOML template is `crates/rein/config/default.toml`.

## Sections

| Section | Purpose |
|---|---|
| `[database]` | SQLite path. `path = "auto"` resolves to the user's Rein data directory. |
| `[embedding]`, `[embedding.google]`, `[embedding.omlx]` | Embedding provider, dimensions, model, endpoint, and optional Google key. |
| `[search]` | RRF/convex-combination fusion, dedup threshold, LLM reranker, MMR, and strong-signal settings. |
| `[chunking]` | Chunk size, overlap, and metadata-prefix behavior. |
| `[sync]` | Supermemory and auto-memory import settings. |
| `[decay]` | Ebbinghaus-style decay constants, pruning threshold, and STM-to-LTM promotion count. |
| `[server]` | HTTP/SSE bind, port, compact mode, GUI flag, loopback auth opt-in, and allowed hosts. |
| `[hooks]`, `[hooks.codex]` | Hook extraction thresholds, context window, buffer location, signal keywords, and Codex hook policy. |
| `[extract]`, `[extract.google]`, `[extract.omlx]` | LLM extraction provider, model, endpoint, prompt cap, and local thinking-mode toggle. |
| `[query_expansion]`, provider subtables | Query expansion provider and maximum expansion count. |
| `[proxy]` | Record-only proxy bind, upstreams, extraction thresholds, retry and buffer limits, and auth opt-in. |
| `[async_memory]` | Async memory worker provider, retries, batching, cooldown, and working-set limits. |
| `[cleanup]` | Consolidation and dedup budgets, thresholds, and inter-batch delay. |
| `[adaptive]` | Adaptive engine enable flag, sample thresholds, event retention, alpha step, and cache TTL. |
| `[intelligent_merge]` | Default-off LLM classifier for gray-zone duplicate decisions. |
| `[resummerize]` | Default-off LLM recompression of flagged canonicals. |
| `[dedup]` | Triple-overlap, N-merge, and temporal-supersede dedup controls. |
| `[ars]`, `[ars.acceleration]` | ARS Cap A/B/C feature flags, batch/cold-start settings, and default-on/fail-closed v0.28 acceleration controls. |
| `[ars.llm_judge]`, `[ars.llm_judge.nightly_cron]` | Default-off runtime judge and offline calibration cron policy (v0.28.7 H0 reverted these defaults from `true` to `false` per the v0.28 charter Non-Goal "Do not make LLM judge default-on"); when explicitly enabled, both are bounded by provider/cost gates. |
| `[llm]`, `[llm.google]`, `[llm.omlx]` | Optional global LLM defaults used by the inheritance resolver. |

## LLM Inheritance

`[llm]` is optional. When present, `ReinConfig::resolve_llm_for(section)` walks
four levels:

1. Section-specific provider table, such as `[ars.cold_archive.google]`.
2. Section-selected provider, such as `[ars.cold_archive].provider`, reading
   provider fields from `[llm.<provider>]`.
3. Global `[llm].provider` plus `[llm.<provider>]`.
4. Hardcoded per-consumer fallback.

Provider-scoped fields are resolved as a unit for the selected provider:
`model`, `api_key_env`, `endpoint`, and `max_input_chars` do not fall across to
another provider's table.

## ARS And Judge Defaults

ARS content-generation capabilities remain opt-in by default. ARS acceleration
is default-on but fail closed: learned parameters do not affect runtime until
`ars_parameter_policy` promotes canary mode with positive scoped adoption
weights. The runtime LLM judge and its nightly calibration cron are
**default-off** in v0.28.7 and later (v0.28.7 H0 reverted both defaults from
`true` back to `false` per the v0.28 charter Non-Goal "Do not make LLM judge
default-on" — operators must explicitly opt in to incur LLM API spend).

| Setting | Default | Notes |
|---|---:|---|
| `[ars].concept_summary_enabled` | `false` | Cap A living summaries stay disabled until enabled. |
| `[ars].recall_synthesis_enabled` | `false` | Cap B recall synthesis also requires a caller to request synthesis. |
| `[ars].cold_archive_enabled` | `false` | Cap C archival summaries are not generated by default. |
| `[ars.acceleration].enabled` | `true` | Acceleration signals are collected and policy is refreshed by default, but runtime adoption remains fail-closed without a healthy canary policy row. |
| `[ars.acceleration].shadow_only` | `false` | Runtime adoption is controlled by `ars_parameter_policy`, not by shadow-only defaults. Missing/corrupt policy, zero scoped adoption weight, drift, or insufficient evidence keep learned parameters out of runtime. |
| `[ars.llm_judge].enabled` | `false` | **v0.28.7 H0 revert.** v0.28.6 had defaulted this `true`, which the 2026-05-02 audit flagged as causing implicit LLM spend on `cargo install` upgrade. Set `enabled = true` in `~/.rein/config.toml` to opt in; once enabled, the judge is bounded by provider resolution, sample rates, daily cap, and per-surface flags. |
| `[ars.llm_judge].synthesis_enabled` | `true` | Applies only after the master `[ars.llm_judge].enabled` flag is true. |
| `[ars.llm_judge].concept_summary_enabled` | `true` | Applies only after the master `[ars.llm_judge].enabled` flag is true. |
| `[ars.llm_judge].recall_ranking_enabled` | `false` | Deferred judge path. |
| `[ars.llm_judge.nightly_cron].enabled` | `false` | **v0.28.7 H0 revert.** Same charter Non-Goal as the master judge flag; cron-mode calibration shares the daily-call ledger with the runtime judge, so its default also reverted from `true` to `false`. Set `enabled = true` in `~/.rein/config.toml` to opt in. |

Use `rein ars-acceleration-gate` or `GET /api/ars-acceleration-gate` to inspect
the read-only canary/default-on release gate. Use `rein trust-measurement` or
`GET /api/trust-measurement` for the combined release gate, eval gates, index
consistency, background observability, and active-learning status.

## Server Startup Policy

`rein serve --sse` and `rein serve --gui` can run one background warmup on
startup to repair side indexes and precompute missing embeddings. Plain stdio
MCP startup does not do this by default because clients such as Codex may start
one `rein serve` process per subagent.

| Setting | Default | Notes |
|---|---:|---|
| `[server].background_warmup` | `true` | Enables service-start background warmup for HTTP/GUI surfaces. Set `false` to require explicit `rein warmup` / `rein doctor --fix`. |
| `[server].stdio_background_warmup` | `false` | Opts plain stdio MCP startup into the same warmup. Keep `false` for Codex agent-team workflows to avoid per-agent side-index rebuilds. |

## Codex Hook Policy

`rein init` installs Codex hook commands, but memory context injection is
explicitly opt-in so fresh installs do not change Codex model context without an
operator decision.

| Setting | Default | Notes |
|---|---:|---|
| `[hooks.codex].inject_prompt_context` | `false` | When true, `UserPromptSubmit` emits bounded `additionalContext` selected from Rein's working set. |
| `[hooks.codex].inject_session_context` | `false` | When true, `SessionStart` emits bounded project context from the always-on index, falling back to the working set. |
| `[hooks.codex].guardrails_enabled` | `true` | Enables deny-only `PreToolUse` and `PermissionRequest` checks for obviously destructive shell commands. |
| `[hooks.codex].max_additional_context_chars` | `1200` | Hard cap for any Codex `additionalContext` payload. Set `0` to disable context output even if injection flags are true. |

## Environment Variables

| Variable | Effect |
|---|---|
| `REIN_CONFIG` | Override the TOML config file path. |
| `REIN_DB` | Override `[database].path`. |
| `GEMINI_API_KEY` | Supplies Google embedding, extraction, and query-expansion API keys when not set in TOML; also the default Google LLM key env. |
| `SUPERMEMORY_CC_API_KEY` | Supplies `[sync].api_key`. |
| `REIN_HTTP_TOKEN` | Bearer/read token for HTTP/SSE, GUI API, and protected reads; required for non-loopback or wildcard HTTP binds unless explicitly opted out where allowed. |
| `REIN_PROXY_TOKEN` | Preferred proxy token; proxy clients may fall back to `REIN_HTTP_TOKEN` in supported helpers. |
| `REIN_SSE_BIND` | Override `[server].sse_bind`. |
| `REIN_SSE_PORT` | Override `[server].sse_port`. |
| `REIN_PROXY_BIND` | Override `[proxy].bind`. |
| `REIN_PROXY_PORT` | Override `[proxy].port`. |
| `REIN_LOG` | Configure tracing filter, such as `warn`, `info`, or `debug`. |
| `REIN_REST_MAX_BODY_BYTES` | Override the REST JSON request body cap; default is 1 MiB. |
| `REIN_LLM_CONCURRENCY` | Override global LLM request concurrency. `0` is treated as invalid and falls back to the default. |
| `REIN_ASYNC_MEMORY_PROVIDER` | Override `[async_memory].provider`. |
| `REIN_ASYNC_P1` | Set to `0` to disable the async open-store connection pool path. |
